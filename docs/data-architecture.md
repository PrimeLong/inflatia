# Какие данные хранит Инфляция — фактическое устройство

Ответ на технические вопросы для юридической оценки (вопросы владельца от 13 ноября 2026; обновлено 22 ноября 2026 после переезда базы на ONREZA). Здесь только факты из кода (`api/`, `src/lib/client.js`, `vercel.json`), проверенные настройки Vercel и прямо помеченные места, которых в коде не видно и которые нужно проверить в панелях провайдеров. Юридических выводов нет — что из перечисленного считать персональными данными, решает юрист (`docs/legal-todo.md`, п. 1–5).

Файл нужно обновлять вместе с `api/_lib/store.js`: новый ключ в базе — новая строка здесь и на странице «Данные и конфиденциальность» (`src/privacy.jsx`).

## Коротко

- База **одна** — **PostgreSQL ONREZA** (`DATABASE_URL`, с 20.11.2026; решение владельца об одной базе — 22.11.2026). В ней две таблицы: `inflatia_kv` — всё, что перечислено в разделе 1 (те же ключи, что раньше в Redis, строками «ключ, поле, значение, срок»), и `inflatia_research` — исследование (своя цель и свои права доступа, раздел «Исследование» ниже). По документации ONREZA база и её резервные копии — в дата-центрах Selectel в Санкт-Петербурге.
- Сайт и серверные функции (`api/*.js`) работают на **Vercel**; функции исполняются в регионе **`arn1` — Стокгольм**. Какая база подключена и где функции — показывает `/api/health` (22.11.2026: `{"ok":true,"db":"postgres","region":"arn1"}`).
- **Upstash Redis** (`iad1`, Вашингтон) с 20.11.2026 не используется рабочим сайтом, но в нём осталась **копия всех данных на 20.11.2026**; переменные Upstash ещё заданы в Vercel (Production и Preview). Удаляется только после проверенной резервной копии ONREZA и решения владельца (`docs/onreza.md`, шаг 7).
- Других сторонних сервисов нет: ни счётчиков посещений, ни рекламы, ни чужих шрифтов, ни почтовых рассылок, ни платежей. Политика безопасности сайта (`Content-Security-Policy` в `vercel.json`) запрещает браузеру обращаться к любым адресам, кроме самого сайта.
- Почту, телефон, настоящее имя, дату рождения и адрес приложение не спрашивает и не хранит.
- IP-адрес в базу попадает только как часть ключа счётчика частоты на один час.
- Cookie приложение не ставит.
- Полный перечень мест, куда могут попасть персональные данные, с географией — раздел 7.

## 1. Какие именно данные сохраняются в базе

Ключи таблицы `inflatia_kv` (имена ключей — как были в Redis). «Срок» — через сколько запись удаляется сама (TTL), если её не трогали.

### Профиль и вход

| Ключ | Что внутри | Срок |
|---|---|---|
| `user:<логин>` | Запись профиля, поля — ниже | бессрочно, до удаления аккаунта |
| `session:<ключ входа>` | Строка `логин:номер_эпохи_пароля` — какому профилю принадлежит ключ входа | 180 дней |
| `card:<логин>` | Карточка для друзей: наряд Инфли (id вещей), серия дней, опыт, уровень, лига, id печатей, число марок, опыт по дням за 21 день, до 20 последних событий (вид, id, время). Свободного текста нет | 180 дней |
| `race:<id забега>` | Забег двух друзей: логины обоих, время приглашения, состояние, число дней | 31 день |

Поля записи `user:<логин>` (`api/account.js`, `api/_lib/accounts.js`):

| Поле | Что это |
|---|---|
| `login` | Логин: латиница, цифры, подчёркивание, 3–20 знаков. Его выбирает ученик |
| `name` | Имя, которое видят другие (ник). Его выбирает ученик |
| `emblem` | Значок профиля (id картинки) |
| `salt`, `hash` | Соль и хэш пароля (scrypt). Сам пароль не хранится |
| `recSalt`, `recHash` | Соль и хэш кода восстановления. Сам код показывается один раз и не хранится |
| `epoch` | Номер «эпохи» пароля: смена пароля делает прежние ключи входа недействительными |
| `playerId` | Случайный идентификатор устройства/профиля (UUID), по нему лежат прогресс и сохранения |
| `birthYear` | Год рождения (только год) |
| `createdAt` | Время регистрации |
| `consentAt`, `pdConsentAt` | Время двух согласий при регистрации: с документом и на обработку данных |
| `parentConsentAt`, `parentName` | Только если по году рождения ученику может быть меньше 14: время подтверждения родителя и **имя родителя, введённое в форме** |
| `stats` | Счётчики сетевой игры: сколько комнат, кварталов, выходов; id последней комнаты |
| `fails`, `lockLevel`, `lockUntil` | Неудачные попытки входа и временная блокировка входа |
| `friends`, `fin`, `fout` | Друзья и заявки: логин → время. `races` — id последних забегов (до 20) |
| `nameAt`, `renameFor`, `renameBy` | Когда меняли ник; требование сменить ник и срок |

### Прогресс и сохранения

| Ключ | Что внутри | Срок |
|---|---|---|
| `profile:<playerId>` | Прогресс: достижения «Мира» (id → время), пройденные учебные модули «Мира», сыгранные посты, свёрнутые блоки интерфейса, и **прогресс учебника и Пути** — пройденные уроки и точность, ответы для повторения с расписанием, серия, опыт и минуты по дням, монеты и история операций, покупки в лавке, сад, копилка, лига, показанные уведомления, место чтения, отметка о связке устройств | 180 дней |
| `solo:<playerId>` | До четырёх сохранённых партий «Мира»: состояние экономики, решения, последние 40 кварталов истории и 40 новостей, название слота | 180 дней |
| `tycoon:<playerId>` | Сохранения «Своего дела» | 180 дней |
| `link:<код>` | Одноразовый код связывания двух устройств → `playerId` | 10 минут |

### Сетевая игра и таблицы

| Ключ | Что внутри | Срок |
|---|---|---|
| `room:<код комнаты>` | Сетевая партия: состояние экономики, решения, история, новости; **имена игроков за постами** (ник профиля или имя гостя), ключи мест (случайные строки), время последней активности каждого места, **сообщения чата комнаты** | 3 дня |
| `public_rooms` | Список кодов открытых комнат | бессрочно (сами комнаты — 3 дня) |
| `daily:<дата>` | Таблица вызова дня: `playerId` → имя (ник или имя гостя), значок, балл, пост, отметка «с профилем» | 31 день |
| `records:tycoon` | Рекорды «Своего дела»: логин → ник, значок, стоимость компании, отрасль, число кварталов, время | бессрочно, строка удаляется с аккаунтом |

### Сообщения об ошибках

| Ключ | Что внутри | Срок |
|---|---|---|
| `reports` | Сообщения «Сообщить об ошибке» (не больше 2000 последних). В каждом: id, время, **логин и ник отправителя**, причина, **текст комментария ученика** (до 1000 знаков), состояние разбора и контекст: экран, вид и id урока и упражнения, условие, **ответ ученика**, правильный ответ, выделенная цитата, версия сборки, **строка браузера и устройства (User-Agent)**, размер экрана | бессрочно в пределах 2000; сообщения ученика удаляются вместе с аккаунтом |

Сообщение «это ошибка фильтра имён» отправляется до регистрации и содержит логин и имя, которые не пропустил фильтр.

Сообщения о сбое экрана (добавлены 13 ноября 2026, `docs/mechanics.md`, «Ошибки экрана») лежат там же: текст ошибки, место в коде, экран, сборка, строка браузера, размер экрана — **без логина, ника и адреса**.

### Счётчики

| Ключ | Что внутри | Срок |
|---|---|---|
| `hit:<действие>:<IP-адрес>` | Число: сколько раз за час с этого адреса регистрировались (`reg`), входили (`login`), восстанавливали пароль (`rec`), слали сообщения (`report-ip`, `report-filter`), слали сбои экрана (`crash`) | 1 час |
| `hit:<действие>:<логин>` | Число: частота сообщений, заявок в друзья, обновлений карточки, приглашений на забег | от 1 минуты до суток |
| `cnt:day:<дата>:<событие>` | Обезличенный счётчик события за день (воронка, уроки, открытия разделов). Без логина, устройства и адреса | 120 дней |
| `cnt:ex:<id упражнения>:…` и `set:…` | Сколько раз упражнение решили верно с первой попытки и всего; список id упражнений и уроков | бессрочно |

### Исследование — та же база, своя таблица (сбор не начат)

Записи исследования (`research/protocol.md`, версия 0.4) — в таблице `inflatia_research` той же базы; отдельная база и переменная `RESEARCH_DATABASE_URL` не нужны. Сбор не начат: `api/research.js` записи не принимает, пока протокол — черновик; таблица появится при первой записи. Поля — только из `research/data-dictionary.md`: код участника, группа, этапы, события обучения и баллы тестов без логина, дат и устройства. Связь с аккаунтом — одна служебная пара `rla:<логин>` ↔ `rlc:<код>`, только для того, что нужно методике (одно участие на человека, 18+ по году рождения, продолжение на другом устройстве, удаление и выгрузка вместе с аккаунтом).

Цели и права доступа разделены в коде (`research/data-dictionary.md`, раздел 1, «Права доступа»): код Инфляции не читает таблицу исследования — кроме «Удалить аккаунт» (стирает участие) и «Скачать мои данные» (отдаёт человеку его записи) через мост `api/_lib/research-link.js`; код исследования узнаёт об аккаунте только логин и год рождения и в таблицу Инфляции не пишет; выгрузка для анализа — только по ключу исследователя и без связи с аккаунтами. Пользователь базы сейчас один (одна строка подключения), поэтому на уровне самой базы таблицы не разделены — это остаточный риск (раздел 7.3).

## 2. Где физически размещена база и можно ли выбрать регион

По документации ONREZA («Размещение данных и сведения для РКН») — дата-центры Selectel в Санкт-Петербурге, Ленинградской области и Москве; основное хранилище PostgreSQL и резервные копии — Санкт-Петербург. В каком именно ЦОД стоит база этого проекта, по адресу не видно — подтвердить у поддержки ONREZA.
- **Функции Vercel** — `arn1` (Стокгольм), выставлено в Settings → Functions 20.11.2026, чтобы запросы к базе не шли через океан.
- **Можно ли выбрать.** Код к провайдеру привязан файлом `api/_lib/pgkv.js` (обычный PostgreSQL по строке подключения): переезд на другой PostgreSQL — новая строка в `DATABASE_URL` и перенос копией `scripts/db-backup.mjs` (`--restore`).
- Upstash (`iad1`, Вашингтон) — бывшая база, хранит копию на 20.11.2026 (раздел 7).

## 3. Сохраняются ли IP-адреса, токены авторизации, сессии и технические логи

**IP-адрес.** Читается из заголовка запроса в `api/account.js` и `api/reports.js` только для ограничения частоты и записывается как часть имени ключа `hit:<действие>:<IP>` со сроком один час. В профиль, сессию, прогресс, сообщения и счётчики аналитики адрес не записывается. `api/events.js` заголовки запроса не читает вовсе.

**Ключ входа (токен).** Случайная строка из 48 шестнадцатеричных знаков. На сервере — ключ `session:<токен>` → `логин:эпоха` на 180 дней. В браузере — в `localStorage` (`ems-account`) вместе с логином, ником, значком и годом рождения. Токен не подписан и не содержит данных — это просто случайный ключ к записи в базе. Выход удаляет запись сессии; смена пароля делает недействительными все прежние ключи.

**Пароль и код восстановления.** Только соль и хэш scrypt.

**Ключи мест в комнате** сетевой игры — случайные строки в записи комнаты, живут вместе с ней три дня.

**Технические логи приложения.** Свой журнал приложение не ведёт. Единственное, что оно пишет в журнал Vercel, — текст необработанной ошибки серверной функции (`console.error('… handler error:', err)` в каждом файле `api/`); тела запросов, логины и адреса туда приложение не выводит. Текст ошибки в редком случае может содержать фрагмент данных запроса.

**Журналы Vercel и ONREZA — вне кода.** Vercel как хостинг сам ведёт журналы запросов к сайту и функциям (IP-адрес, адрес страницы, время, строка браузера); журнал функций на тарифе Hobby хранится 1 час, Log Drains не включены. ONREZA ведёт свои служебные журналы подключений к базе (подключаются только функции Vercel); что именно и сколько хранит — не описано, спросить у поддержки. Подробно — раздел 7.

## 4. Какие данные передаются Vercel, ONREZA и другим сторонним сервисам

**Vercel** (хостинг сайта и серверных функций) получает всё, что браузер отправляет на сайт: сами запросы (IP-адрес, строка браузера, время) и их содержимое — логин и пароль при входе и регистрации (в открытом виде внутри HTTPS; на сервере пароль сразу хэшируется), ник, год рождения, имя родителя, прогресс, сохранения, сообщения об ошибках, имена и чат в сетевой комнате. Серверные функции исполняются на машинах Vercel в Стокгольме (`arn1`).

**ONREZA** (база) получает от серверных функций всё перечисленное в разделе 1 и записи исследования — и только это. Пароль в открытом виде в базу не попадает. **Upstash** с 20.11.2026 новых данных не получает (кроме превью-сборок, раздел 7), но хранит копию на 20.11.2026.

**Другие сервисы — нет.** В зависимостях приложения (`package.json`) нет SDK аналитики, рекламы, платежей, почты или отслеживания ошибок; `Content-Security-Policy` разрешает браузеру соединения только с самим сайтом (`connect-src 'self'`), шрифты, картинки, звук и музыка лежат на самом сайте. Автотест (e2e) падает, если страница обратилась к чужому адресу.

Исключения, не связанные с данными учеников:

- при **сборке** сайта скрипт `scripts/fetch-portraits.mjs` скачивает портреты экономистов с Wikimedia Commons — это запрос сборочной машины, не браузера ученика;
- голос сюжетов может синтезировать **сам браузер** (Web Speech API). Какой движок синтеза использует браузер и отправляет ли он текст на свой сервер, зависит от браузера и системы; приложение передаёт ему только текст сюжета урока, без данных ученика;
- репозиторий и сборки проходят через **GitHub** (код и автотесты, без данных учеников).

**Обезличенные счётчики** (`api/events.js`) — уходят на тот же сайт и в ту же базу; в запросе только название события и, для упражнений, id урока и упражнения, «верно/неверно» и время ответа.

## 5. Есть ли резервные копии и где они хранятся

- **Приложение само копий не делает**, но с 22.11.2026 есть скрипт `scripts/db-backup.mjs`: владелец снимает копию обеих таблиц на свой компьютер, проверяет её и разворачивает в другой базе для сверки (`docs/onreza.md`, «Резервные копии»). Основная защита — восстановление на момент времени (PITR) ONREZA.
- **Копии на стороне ONREZA:** PITR (на Hobby и Pro) и независимая копия; по документации ONREZA — Санкт-Петербург. Окно восстановления — **проверить в панели ONREZA** и записать сюда.
- **Копия у самого ученика:** кнопка «Скачать мои данные» в профиле отдаёт файл JSON с его профилем, согласиями, прогрессом, сохранениями, друзьями и сообщениями (`api/account.js`, действие `export`). Прогресс также лежит в `localStorage` браузера и сливается с серверным.
- **Важно для оценки:** удалённый аккаунт остаётся в резервных копиях до истечения их срока (PITR ONREZA, ручные копии владельца) и в копии Upstash на 20.11.2026, пока она не удалена, — «Удалить аккаунт и все данные» стирает записи только из рабочей базы.

## 6. Можно ли выгрузить полный список таблиц и полей базы

Да — он в этом файле: раздел 1 перечисляет **все** ключи и поля, которые пишет код; других мест записи, кроме `api/_lib/store.js`, нет. Проверить можно тремя способами:

1. **По коду:** все обращения к таблице `inflatia_kv` — в одном файле `api/_lib/store.js`, к `inflatia_research` — в `api/_lib/research-store.js` и мосте `api/_lib/research-link.js`; поля профиля — `api/account.js` (регистрация) и `api/_lib/accounts.js`.
2. **По живой базе:** запросом `SELECT split_part(k, ':', 1), count(DISTINCT k) FROM inflatia_kv GROUP BY 1` (или копией `scripts/db-backup.mjs`) увидеть фактические ключи и их число по префиксам: `user:`, `session:`, `card:`, `race:`, `profile:`, `solo:`, `tycoon:`, `link:`, `room:`, `public_rooms`, `daily:`, `records:`, `reports`, `hit:`, `cnt:`, `set:`. Ключей с другими префиксами быть не должно (старый `league-names` стирается при запуске).
3. **По одному ученику:** «Скачать мои данные» показывает всё, что хранится о конкретном профиле.

## Что хранится только в браузере ученика (не в базе)

`localStorage` на устройстве: ключ входа и краткие данные профиля (`ems-account`), прогресс до входа и его рабочая копия (`ems-textbook-v1`), автосохранение партии, настройки (тема, музыка, громкость, размер текста, черновик), отметки «уже показано» (уведомление о памяти браузера, знакомства, церемонии), случайный `playerId`, отметки разовых событий аналитики (какие события уже отправлены с этого устройства). Cookie нет. Service worker хранит в кэше браузера файлы самого сайта для работы без сети.

| Что | Сколько хранится | Как удаляется |

Участие в исследовании удаляется вместе с аккаунтом.

## 7. Цепочка обработки: все места, куда могут попасть персональные данные (проверено 22.11.2026)

Как проверено: код (`api/`, `src/`, `vercel.json`, `package.json`), переменные окружения и настройки проекта в Vercel (только имена и даты, без значений), `/api/health` и журналы рабочего сайта через панель Vercel. Чего не видно ни в коде, ни в панели Vercel, помечено «не проверено».

### 7.1. Путь одного запроса

Браузер ученика → ближайший узел сети Vercel (HTTPS; страницы и файлы отдаются отсюда же) → функция `api/*.js` в Стокгольме (`arn1`) → PostgreSQL ONREZA (TLS с проверкой сертификата, пул PgBouncer) в Санкт-Петербурге. Ответ — тем же путём. Ни браузер, ни функции не обращаются к другим адресам: `connect-src 'self'` в браузере, в серверном коде нет запросов к чужим сервисам.

### 7.3. Остаточные риски цепочки

- Сервер в ONREZA Compute подготовлен, но не включён (7.5): пока рабочий сайт на Vercel, обработка запросов — в Швеции.

- Обработка запросов (Vercel Functions, Стокгольм) и журналы Vercel — **за пределами России**; база — в России. Нужна ли полная локализация обработки — вопрос к юристу (`docs/legal-todo.md`, п. 1–2; варианты замены — `docs/onreza-migration-plan.md`, раздел 5).
- Копия всех данных в **Upstash (США)** до её удаления.
- **Пароль базы не сменён** после того, как строка подключения была передана в чате 20.11: переменная `DATABASE_URL` (Production) создана 20.11.2026 в ~07:12 UTC и с тех пор не менялась (дата изменения в Vercel совпадает с датой создания).
- Временные переменные переноса ещё заданы: `MIGRATE_TOKEN` и `DATABASE_URL` для превью ветки `claude/gallant-hawking-2qacnf` — эта строка ведёт в рабочую базу.
- Один пользователь базы на обе таблицы: разделение исследования и Инфляции — в коде, не в правах базы.
- Журналы ONREZA и окно PITR — не проверены.

### 7.5. После переноса сервера в ONREZA Compute (подготовлено 24.11.2026, не переключено)

Код готов (`server/`, `scripts/build-onreza.mjs`, `onreza.rules.toml`; `docs/onreza.md`, «Перенос сервера в ONREZA Compute»),
рабочий сайт пока на Vercel — таблица 7.2 описывает действующую схему. После переключения путь запроса:

Браузер ученика → Edge ONREZA (правила, HTTPS) → статика — CDN ONREZA, `/api/*` — сервер Express в ONREZA Compute
(Ленинградская обл., ЦОД Selectel в Дубровке, по сведениям ONREZA на 13.10.2026) → PostgreSQL ONREZA (вычисления — там же,
хранилище и копии — Санкт-Петербург). Сервер, как и функции Vercel, никуда, кроме базы, данные не отправляет; Upstash в
Compute не подключается даже при заданных переменных (`api/_lib/store.js`).

| Место | Что меняется после переключения |
|---|---|
| Vercel Functions, сеть и журналы Vercel | не участвуют в обработке; проект Vercel остаётся на паузе для отката, пока не удалён; после переадресации старый адрес видит только запрос перехода |
| ONREZA Compute | все данные запросов — на время запроса, в памяти процесса; на диск не пишется (файловая система процесса временная) |
| Журналы ONREZA (Access Logs) | время, метод, путь, код ответа, длительность, **IP-адрес** клиента; на Hobby видно 30 минут, на Pro — до 7 дней; **где и сколько хранятся — в документации нет**, спросить у поддержки. Пишет ли журнал строку запроса (`?playerId=…`, `?token=…` у GET `/api/solo`, `/api/daily`, `/api/room`) — не проверено |
| Журнал сервера (`console.error`) | только имя обработчика, метод, путь и текст ошибки — без тела запроса |
| CDN статики ONREZA | IP-адрес и адреса страниц — транзит; **где узлы — не указано** |
| Адрес клиента | только для лимитов частоты, в ключах `hit:` на час; берётся у доверенного прокси (`TRUST_PROXY_HOPS`, `CLIENT_IP_HEADER`) |
| Браузер ученика | новый адрес сайта — новое хранилище браузера: прежнее остаётся на `inflatia.vercel.app` (`docs/onreza.md`, «Переключение») |

Соответствие 152-ФЗ из размещения в ONREZA само не следует: оператор, поручение обработки (на Hobby ONREZA его не
подписывает), уведомление РКН, согласия — `docs/legal-todo.md`.
